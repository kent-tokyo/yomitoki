# Synthesizability benchmark

External accuracy/selective-prediction/throughput benchmark for yomitoki,
separate from the core Rust crate on purpose: this directory pulls in
Python + RDKit + scikit-learn + competitor packages, none of which belong
in yomitoki's own dependency tree.

**Read the results first**: [`docs/benchmark.md`](../../docs/benchmark.md)
(repo root) is the actual report — dataset provenance, accuracy tables,
selective-prediction findings, throughput, limitations, reproduction
steps. This directory is the harness that produced it.

## Layout

```
benchmarks/synthesizability/
  README.md              this file
  requirements.txt        pinned harness dependencies (numpy/scipy/pandas/sklearn/rdkit/pytest)
  datasets/
    README.md              full provenance for every dataset/competitor: source, license,
                            SHA256, expected record count, preprocessing/exclusion rules
    downloaded/             gitignored — regenerated by download_brsascore.py
  scripts/
    metrics.py               ROC-AUC/PR-AUC/bootstrap-CI/risk-coverage/AURC/calibration
                              (no dataset-specific code; unit-tested against synthetic
                              fixtures only, see test_metrics.py)
    test_metrics.py           pytest suite for metrics.py; this is what CI's
                              benchmark-smoke job runs — statistics only, no RDKit/network
    normalize_direction.py    per-method score-direction table + transform
    download_brsascore.py     fetches + verifies + preprocesses TS1/TS2/TS3
    run_yomitoki.py            batch-scores a .smi file with the yomitoki CLI
    run_sascore.py             batch-scores a .smi file with RDKit's sascorer.py
    run_brsascore.py           batch-scores a .smi file with the BRSAScore PyPI package
    merge_and_evaluate.py      joins ground truth + all methods' scores, computes every
                              accuracy/selective-prediction metric, writes results/
    benchmark_throughput.py    Phase C: same-machine throughput for all three methods
  competitors/
    README.md                install/run instructions per competitor (or, for SYBA,
                              why it's excluded)
  results/
    benchmark_summary.json    committed — accuracy + selective-prediction, aggregate only
    selective_prediction.csv  committed — risk-coverage points per dataset
    timing.json                committed — throughput + machine info
    per_molecule.jsonl         gitignored — reproduces dataset SMILES, regenerate locally
    raw/                       gitignored — per-method raw scores, regenerate locally
```

## Quick start

```
pip install -r requirements.txt
pip install BRSAScore --no-deps   # see competitors/README.md for why --no-deps
python3 scripts/download_brsascore.py datasets/downloaded
cargo build --release --bin yomitoki   # from repo root

for ds in ts1 ts2 ts3; do
  python3 scripts/run_yomitoki.py  datasets/downloaded/brsascore/$ds.smi results/raw/${ds}_yomitoki.jsonl
  python3 scripts/run_sascore.py   datasets/downloaded/brsascore/$ds.smi results/raw/${ds}_sascore.jsonl
  python3 scripts/run_brsascore.py datasets/downloaded/brsascore/$ds.smi results/raw/${ds}_brsascore.jsonl
done
python3 scripts/merge_and_evaluate.py
python3 scripts/benchmark_throughput.py
```

## Design rules this directory follows

- **No large datasets or third-party model files committed to git.**
  Everything under `datasets/downloaded/` and `results/raw/` is
  regenerated by a script, gitignored, and documented (source URL,
  license, SHA256, record count, preprocessing/exclusion rules) in
  `datasets/README.md` — not silently substituted if unobtainable.
- **Score direction is a table, not inline logic** — see
  `scripts/normalize_direction.py`. Every entry states where the
  direction was verified (source code + empirical spot-check), never
  assumed from an abstract or a usage example.
- **Frozen baseline first.** yomitoki is measured with its shipped
  v0.1.0 default config; no weight/threshold/formula was changed while
  looking at these results, and TS1/TS2/TS3 are confirmatory-only going
  forward — see `docs/benchmark.md`'s "Test-set integrity" section.
- **Coverage is always reported, never silently dropped.** Every
  evaluation records total / scored / failed per method.
